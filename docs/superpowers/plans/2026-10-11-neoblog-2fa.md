# NeoBlog 两步验证（TOTP 接口 + 登录分叉 + 密钥加密 + 重放防护）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 兑现 2FA schema 轮的消费规则：5 条新接口（setup / enable / disable / recovery-codes / verify）+ 登录二段分叉 + `/auth/me` 状态暴露 + secret AES-GCM 加密 + 二段会话内限次 + `totp_last_counter` 列防重放 + enable/disable 吊销其它会话。

**Architecture:** 照 auth 模块既有分层（module → controller → service → repository）增量扩展；pending 态用 scs 独立会话键承载（守卫零改动）；恢复码消费与 TOTP 重放认领都用单条条件 UPDATE 原子决胜负；多写操作走 `client.Tx`（沿用 access/settings 先例）；一个迁移：`users` 加 `totp_last_counter`。

**Tech Stack:** Go 1.27 + Gin + ent + scs + `github.com/pquerna/otp`（唯一新增依赖）+ Atlas 版本化迁移 + Postgres 17。

**Spec:** `docs/superpowers/specs/2026-10-11-neoblog-2fa-design.md`（v1.2，本计划实现它；执行者两份都要读，三态语义在 spec §4，接口/错误码在 §5/§7，重放规则在 §5.5，**窗口纪律在 §8 表下方那段——不看它 Task 6 必红**）

## Review Focus

1. **双花/重放竞态**：恢复码消费与 TOTP 计数认领都必须单条条件 UPDATE 判断影响行数，禁止读后写——并发同码必须恰一人成功。测试：Task 3 两条并发断言 + Task 6 ⑪。
2. **pending 会话越权与态污染**：pending 打受保护接口 401；进入 pending 必须清 `auth.user_id`（已登录会话再登 2FA 账号不得两态并存）；verify 成功后两把 pending 键清干净。测试：Task 6 ①⑭。
3. **限次边界**：第 5 次错码 `two_factor_locked` + 销毁；销毁后正确码也进不去；重走登录可恢复。测试：Task 6 ③。
4. **密钥失败面**：配置缺失/非法启动失败；落库必为密文；**解密失败或 secret 本身非法 = 500 `internal_error`**、不耗限次、不销毁会话（密钥轮换/损坏不得伪装成验证码错误）。测试：Task 1 单测 + Task 4 非法 base32 用例 + Task 5 ⑧ + Task 6 ⑫。
5. **半程失败与态一致性**：enable（置位+插码）、disable（清三列+删码）、regen（删旧+插新）单事务——成功必全成；setup 覆盖清计数；enable/disable 的**吊销排在落库之前**，吊销失败则本次动作整体不生效（杜绝「库里已启用、恢复码没发出去」的 409 死角）。测试：Task 5 各生命周期后态断言 + ⑬。
6. **窗口纪律（不做则 Task 6 主链必红）**：enable 会认领掉当前 30 秒窗，因此「先 enable/verify 成功、之后再验一次正码」的用例必须经 `totpNow` 接缝把窗口前移再取码；严禁靠真实时钟恰好跨窗通过，也不要在测试里 `sleep` 30 秒。测试：Task 4 建接缝与取码 helper，Task 6 ①③⑫⑭ 使用它，⑪ 反向钉在同窗。

### Task 4: TOTP 与恢复码纯函数原语

**Files:**
- Create: `backend/internal/modules/auth/totp.go`
- Test: `backend/internal/modules/auth/totp_test.go`

**Interfaces:**
- Produces:
  - `type totpSetup struct { Secret string; OTPAuthURL string }`
  - `generateTOTPSetup(accountName string) (totpSetup, error)`——Issuer 固定 `NeoBlog`
  - `matchTOTPCounter(code, base32Secret string, now time.Time) (int64, bool, error)`——候选窗 `{⌊now/30⌋-1, ⌊now/30⌋, ⌊now/30⌋+1}` 逐窗 `GenerateCode` 常数时间比较，命中返回该窗计数；**secret 本身非法（base32 解不开、`GenerateCode` 报错）必须走 `error`**，与「码没匹配上」严格区分；非 6 位数字是 `(0, false, nil)`
  - 包内时间接缝 `var totpNow = time.Now`——auth 模块唯一取时点，service/controller 一律经它；测试用 `t.Cleanup` 临时替换以确定性推进窗口（集成测试因此不需要 `sleep`）。全仓现状无 `t.Parallel()` 用例，本轮 2FA 用例也**不得加并行**，否则替换包级变量会互相打架
  - 测试 helper（放 `totp_test.go`，Task 5/6 续用）：`codeAt(secret string, counter int64) string` 按窗号取码；`pinWindow(t *testing.T, secret string, counter int64) string` 把 `totpNow` 冻结到该窗中点（`t.Cleanup` 还原）并返回该窗的码——**同一个用例里每次需要「再次成功认领」就取更大的窗号**，全程零 `sleep`、与真实时钟无关
  - `generateRecoveryCodes(count int) ([]string, error)`——32 位小写 hex，批内唯一
  - `hashRecoveryCode(code string) string`——**归一化单点**：内部 `ToLower(TrimSpace(code))` 后 sha256 hex（64 字符）；调用方传原始输入
